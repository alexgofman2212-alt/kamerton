# Камертон — передача работы

Сжатый итог первой сессии разработки. Читать вместе с `README.md` (запуск, механика, формат каталога) и `CLAUDE.md` (правила работы в проекте).

## Что просил заказчик

Приложение, чтобы выучить основные классические произведения на слух:

- звучит фрагмент, даётся 5 вариантов ответа;
- угадал — растёшь в ранге, нет — «нужно стараться больше»;
- с ростом ранга сложнее: сначала фрагменты 10–15 с, потом 5 с, причём не самые растиражированные места;
- режимы: по эпохам и «слабые места» (в том числе заданные вручную — погонять по конкретным композиторам);
- пошаговая система с напоминаниями и повторением усвоенного, «чтобы человек не отлынивал»;
- стильный дизайн, интуитивный интерфейс.

Решения, которые заказчик принял явно: **PWA**, **публичный запуск**, **около 60 произведений** в первой версии, **русский интерфейс**.

### Механика в цифрах

- Ранги и пороги опыта: Слушатель 0, Любитель 150, Меломан 450, Ценитель 900, Знаток 1600, Эрудит 2600, Маэстро 4000.
- Длина фрагмента по уровням 1–7: 15, 12, 10, 8, 6, 5, 4 с. Доля фрагментов из середины записи: 0, 0, 40 %, 70 %, 90 %, 100 %, 100 %.
- Уровень вопроса = минимум из ранга и (ступень произведения + 2): новое произведение даётся легко даже Маэстро.
- Опыт за верный ответ: 10 + 2 × уровень + серия (до 5) + 3 за ответ до конца фрагмента. За неверный — 0.
- Ступени повторения: интервалы 1, 2, 4, 8, 16, 32 дня. «Освоено» — со ступени 4.
- Ошибка: ступень падает до 1, произведение возвращается в конец занятия (не больше 3 таких возвратов). Верный ответ в день ошибки ступень не поднимает.
- Слабое место: закреплено вручную, либо были ошибки и ступень ≤ 2, либо точность ниже 60 % при 3+ ответах.
- Каталог открывается по уровням: 36 произведений сразу, ещё 31 с ранга «Любитель», ещё 17 с «Меломана». В режимах «эпохи» и «композиторы» доступно всё сразу.
- Занятие — 10 вопросов.

## Что не сделано и не проверено

1. **Записи никто не слушал.** Соответствие «файл — произведение — часть» взято из описаний на Commons.
2. **`hook` у пяти записей выставлен оценочно** (секунда начала знаменитой темы): Россини 480, Сметана 62, Элгар 118, Штраус 100, «Вальс цветов» 70.
3. **Реальное воспроизведение с Wikimedia в браузере не проверено.** Один файл скачан напрямую и оказался валидным MP3; браузер контейнера через прокси до Wikimedia не дошёл.
4. **Анализ звука** (пропуск тишины в начале, выбор мест из середины) сделан для 1 записи. У остальных `intro = 0`, а места заданы долями длительности (30, 42, 54, 66, 78 %).
5. **Исполнители.** У 27 записей `"artist": ""` — на Commons указан только композитор. Девять из них под CC BY / CC BY-SA, для них исполнитель обязателен: `bach-brandenburg-3`, `mozart-nachtmusik`, `mozart-pc21`, `mozart-sym25`, `beethoven-moonlight-3`, `schubert-ave-maria`, `liszt-liebestraum`, `tchaikovsky-sugar`, `dvorak-humoresque`.
6. **Аккаунтов и синхронизации нет**, хотя заказчик выбрал публичный запуск. Точка расширения — интерфейс `ProgressStore` в `src/engine/progress.ts`.
7. **Push на закрытое приложение** требует сервера Web Push. Сейчас: таймер при открытом приложении, Periodic Background Sync (только установленное PWA на Android, не проверено), файл `.ics`.
8. **Качество части записей низкое**: старые пластинки (Гайдн «Сюрприз», Равель «Болеро» 1935 г., Верди, Брамс «Колыбельная», Дебюсси «Фавн») и синтезированные исполнения Кевина Маклауда (Пахельбель, Вагнер «Свадебный хор», «Хабанера»). Кандидаты на замену.
9. **Юридической проверки не было.**
10. **Git**: репозиторий инициализирован локально, коммитов нет — заказчик о них не просил.

## Что делать дальше, по приоритету

1. Запустить у заказчика (`npm install`, `npm run dev`) и убедиться, что звук с Wikimedia играет в обычном браузере. Если нет — сразу переходить к своему хостингу аудио.
2. `npm run catalog:analyze` на машине заказчика (нужен `ffmpeg`): домашний IP под жёсткий лимит попадать не должен.
3. Прослушать библиотеку, поправить ошибочные записи и `hook`, заменить записи низкого качества.
4. Заполнить исполнителей для девяти записей из п. 5.
5. Решить с заказчиком серверную часть (аккаунты, синхронизация, push) и хостинг аудио — оба вопроса заданы, ответа пока нет.
6. Выложить на статический хостинг с HTTPS, проверить установку PWA и напоминания на телефоне.

## Особенности окружения, на которые уже наступили

- **Wikimedia API** (`commons.wikimedia.org/w/api.php`) без осмысленного `User-Agent` отвечает 429. С облачного IP лимит оконный и общий на пул адресов: несколько запросов проходят, дальше 429 с `Retry-After`. Работает только одно: ждать ровно `Retry-After` и слать запросы подряд. Фиксированные паузы хуже.
- **`upload.wikimedia.org`** с облачного IP отдаёт один-два файла, затем 429 с `Retry-After: 600`. Подмену `User-Agent` под браузер делать нельзя — это обход ограничения сервиса, и в облачной сессии такое действие блокируется.
- **Node `fetch` в облачном контейнере** не ходит через прокси сам: нужен `NODE_USE_ENV_PROXY=1`. На обычном компьютере это не требуется.
- **Playwright** в облачном контейнере установлен глобально; `tools/e2e.mjs` и `tools/make-icons.mjs` берут его из проекта, а если его там нет — через `NODE_PATH` (в контейнере `/opt/node22/lib/node_modules`).
- **Cormorant Garamond** по умолчанию рисует старостильные цифры («10» выглядит как «IO»); в `styles.css` включены `lining-nums` — не убирать.
