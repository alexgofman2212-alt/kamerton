# Камертон

PWA-тренажёр: звучит фрагмент классического произведения, нужно выбрать его из пяти вариантов. Чем выше ранг, тем короче фрагменты и тем менее очевидные места из записи.

## Запуск

Нужен Node.js 20+.

```powershell
npm install
```

```powershell
npm run dev
```

Сборка и локальный просмотр готовой версии (с service worker и установкой как приложения):

```powershell
npm run build
```

```powershell
npm run preview
```

Проверки:

```powershell
npm test
```

```powershell
npm run e2e
```

`npm run e2e` гоняет приложение в браузере (нужен Playwright: `npm i -D playwright` и `npx playwright install chromium`). Записи в тесте подменяются тоном, сгенерированным в памяти, — сеть и ffmpeg не нужны.

## Как устроено обучение

- **Ранги** (`src/engine/rules.ts`): Слушатель → Любитель → Меломан → Ценитель → Знаток → Эрудит → Маэстро. Опыт даётся только за верные ответы; больше — за сложный уровень, серию и ответ до конца фрагмента.
- **Сложность вопроса** — минимум из ранга и того, насколько усвоено само произведение. Фрагмент: 15 → 12 → 10 → 8 → 6 → 5 → 4 с. На первых уровнях он берётся с начала (знаменитая тема), дальше всё чаще из середины. Неверные варианты на низких уровнях далеки от ответа, на высоких — та же эпоха, тот же композитор, тот же состав.
- **Каталог открывается постепенно**: уровень 1 — сразу, 2 — с ранга «Любитель», 3 — с «Меломана».
- **Интервальное повторение** (`src/engine/progress.ts`): ступени с интервалами 1, 2, 4, 8, 16, 32 дня. Ошибка возвращает произведение на первую ступень и в «Слабые места»; оно уходит оттуда после двух верных ответов в разные дни.
- **Режимы**: тренировка дня (повторения + слабые места + новое), по эпохам, по композиторам, слабые места (ошибки и закреплённое вручную).
- **Напоминания** (`src/reminders.ts`, `public/reminder-sw.js`): уведомление, пока приложение открыто; Periodic Background Sync в установленном PWA на Android; файл календаря `.ics` для всех остальных случаев.

Прогресс хранится в `localStorage` через интерфейс `ProgressStore` — серверную синхронизацию можно добавить отдельной реализацией.

## Каталог записей

Источник — `tools/catalog-src.json`: композиторы и произведения с названием файла на Wikimedia Commons. Из него собирается `src/data/catalog.json`:

```powershell
npm run catalog
```

Скрипт берёт с Commons длительность, лицензию, автора и MP3-версию и **отбрасывает записи с лицензией не из разрешённого списка** (Public domain, CC0, CC BY, CC BY-SA).
Записи CC BY и CC BY-SA с явно пустым `artist` остаются в исходном каталоге, но не публикуются. Для первого релиза это 9 записей; доступно 75 произведений. Когда поле отсутствует, атрибуция берётся из метаданных Commons.

С анализом звука (нужен `ffmpeg` в PATH) — точное начало музыки и шесть «неочевидных» мест без провалов в тишину:

```powershell
npm run catalog:analyze
```

Со своим хостингом записей — копии в `public/audio`, приложение перестаёт зависеть от серверов Wikimedia:

```powershell
npm run catalog:selfhost
```

Wikimedia ограничивает частоту запросов; скрипт сам ждёт столько, сколько просит сервер, и продолжает с места остановки (кеш в `tools/cache`).

### Добавить произведение

Запись в `pieces` файла `tools/catalog-src.json`:

```json
{
  "id": "mozart-turca",
  "composer": "mozart",
  "title": "Турецкий марш",
  "part": "Соната № 11, III. Rondo alla turca",
  "year": "1783",
  "kind": "piano",
  "tier": 1,
  "file": "Rondo Alla Turka.ogg",
  "artist": "исполнитель",
  "hook": 0
}
```

- `file` — имя файла на Commons без `File:`.
- `kind` — `orchestra`, `piano`, `vocal`, `chamber`, `organ`, `solo`; влияет на подбор неверных вариантов.
- `hook` (необязательно) — секунда, с которой звучит знаменитая тема, если она не в начале записи.
- `artist` (необязательно) — исполнитель для страницы «Записи и лицензии»; без него берётся поле с Commons.

## Что нужно доделать перед публичным запуском

1. **Проверка на слух.** Записи подобраны по описаниям на Commons, никто их не прослушивал. Нужно пройти библиотеку и убедиться, что каждая запись — то произведение и та часть, а `hook` у пяти записей (Россини, Сметана, Элгар, Штраус, «Вальс цветов») попадает в знаменитую тему: значения выставлены по типичной структуре произведений.
2. **Исполнители.** У части записей поле автора на Commons называет только композитора; в `catalog-src.json` у них `"artist": ""`. Для записей под CC BY и CC BY-SA исполнителя нужно выписать со страницы записи.
3. **Свой хостинг аудио.** Сейчас записи играют прямо с `upload.wikimedia.org`. Для публичной нагрузки надёжнее `npm run catalog:selfhost` и раздача с собственного хостинга или CDN.
4. **Аккаунты и синхронизация.** Не сделаны: прогресс живёт на устройстве, перенос — через файл в настройках.
5. **Push-уведомления.** Гарантированная доставка на закрытое приложение требует сервера Web Push.
6. **Юридическая проверка.** Набор лицензий подобран консервативно, но это не юридическое заключение.

## Развёртывание

Приложение настроено для `https://alexgofman2212-alt.github.io/kamerton/`. После отправки изменений в `main` workflow `.github/workflows/deploy.yml` запускает тесты, собирает `dist` и публикует его в GitHub Pages. В настройках репозитория Pages источником должен быть выбран **GitHub Actions**.

Проверки перед отправкой: `npm test`, `npm run build`, `npm run e2e`, `node tools/smoke-pwa.mjs` и `node tools/smoke-audio.mjs`. Для последних двух нужен установленный Playwright Chromium (`npx playwright install chromium`). `smoke-audio` обращается к Wikimedia и зависит от доступности её серверов.

После публикации проверьте адрес с телефона и установку PWA через меню браузера. Интерфейс доступен без сети после первого открытия, но записи загружаются с Wikimedia и для воспроизведения требуют интернета.
